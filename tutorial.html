From Blender to Browser

Creative Tech 1 · Project 0. This tutorial takes you from an empty Blender file to a web page where a visitor clicks a part of your object, the part animates away, a fact appears, and a language model responds to it. You will model a simple block object, render it to sprite sheets, wire it into HTML, CSS and JavaScript, and then call a model three ways: Ollama on your own computer, Claude, and OpenAI. Work through it in order. Each part ends with a checkpoint you can test.

Everything you need is in one GitHub repository The template site, the Blender example, the render script and a list of resources: github.com/Geitenkaas/CreativeTech_Project0

Step 2: Run it

The page loads JSON files with fetch(), and browsers only allow that from a web server, not from a file you double-click. Start a small server in the project folder:

On a Mac, use python3 if python is not found. Leave it running and open http://localhost:8000. Press Ctrl+C in the terminal when you want to stop it.

Part 2: A block object in BlenderDraw it like pixel art, then give it depth

The method: draw your object flat on a grid of squares, as if each square were a pixel. Split the drawing into parts. Push it all out into blocks. Because every edge follows the grid, the result looks like chunky 3D pixel art. Open blender/glasses.blend to see a finished one.

Plan first, on paper. Choose an object with four or more parts that could plausibly come apart. Sketch it on squared paper, about 16 squares across. Decide which squares belong to which part.

Step 3: Set up Blender

  1. Install Blender (free; version 4.2 or newer). A mouse with a scroll wheel makes it much easier.
  2. Open it and choose File → New → General.
  3. Hover over the main 3D view, press A to select everything, then X → Delete. This removes the starting cube, camera and light. The render script will make a camera and light that fit your object.
Blender shortcuts go to whatever your mouse is over. If a key does nothing, move the pointer over the 3D view and press it again. Ctrl+Z (Mac: Cmd+Z) undoes.

Step 4: Draw with a grid

  1. Press Shift+A → Mesh → Grid.
  2. A small panel named Add Grid appears at the bottom left of the 3D view. Open it and set X Subdivisions and Y Subdivisions to the same number (16 is a good start) and Rotation X to 90. Using the same number both ways keeps your pixels square. The rotation stands the grid upright, facing the front.
  3. Look from the front (Numpad 1 or View → Viewpoint → Front). You should see a flat sheet of squares.
  4. Press Tab to enter Edit Mode, then 3 on the top row of your keyboard for face select (or click the third of the three small select-mode icons at the top left of the 3D view).
  5. Select the squares that are not part of your object: click one, Shift+click to add more, or press C and paint over them (right-click to finish painting).
  6. Press X → Faces. What is left is your drawing.

Step 5: Split it into parts

Each part that should move on its own must be its own object.

  1. Still in Edit Mode, select all the squares of one part.
  2. Press P → Selection. Those squares become a new object.
  3. Repeat for every part except the last one, which is what remains.
  4. Press Tab to return to Object Mode.
  5. Name each part. In the Outliner (the list at the top right), double-click a name and type a short one in lower case: body, cap, screen. These names become the ids you use in your facts, so keep them simple.

Step 6: Give it depth

  1. In Object Mode, press A to select every part.
  2. Press Tab. You are now editing all the parts at once.
  3. Press A to select every square, then E to extrude. Type 0.3 and press Enter.
  4. Press Tab to leave Edit Mode, and orbit around to look at your blocks.

For a part that should be thinner or thicker (a lens, a button), select only that part, Tab, A, E, and type a different number.

Step 7: Colour the parts

  1. At the top right of the 3D view there is a row of four small spheres. Click the third one, Material Preview, so you can see colours.
  2. Click one part. In the panel at the bottom right, open the Material tab (the checkered sphere icon near the bottom of the column of icons).
  3. Press New, then click the Base Color swatch and choose a colour.
  4. Repeat for each part. Flat, strong colours suit this style.
Checkpoint You have four or more named, coloured block parts that together form your object. Save now: File → Save As, and save it inside your project's blender folder, for example blender/battery.blend. The render script needs it there.

Step 8: Animate it apart

You only set two moments: the start, with everything in place, and the end, with the parts apart. Blender works out the frames in between. Twelve frames is plenty.

  1. Find the Timeline along the bottom of the window. At its right-hand end, set End to 12.
  2. Make sure you are in Object Mode and on frame 1 (the number just left of Start).
  3. Press A to select every part, then press I with the pointer over the 3D view. If a menu appears, choose Location. This records where everything is on frame 1. Small diamonds appear in the Timeline.
  4. Change the frame number to 12.
  5. Click one part. Press G and move the mouse to drag it away, then click to drop it. To move in a straight line, press G then X (sideways), Z (up and down) or Y (towards and away from the front).
  6. Press I again to record the new position on frame 12.
  7. Repeat steps 5 and 6 for each part you want to move. Leave at least one part where it is, as the body the others leave.
  8. Press Space to play it. Press Space again to stop.
If a part jumps back when you change frame, you moved it but did not press I. A move only counts once a keyframe records it.
Checkpoint Pressing Space shows your object coming apart over 12 frames and snapping back to the start. Save with Ctrl+S.

Part 3: Render to sprite sheetsOne image per part, with every frame side by side

Step 9: Run the render script

A sprite sheet is one image holding every frame of an animation in a row. You could render 12 images per part and paste them together by hand in Photoshop, as you did in From Shell to Sprites. The script make_sprites.py does the same job for every part at once.

  1. Check your .blend is saved inside the project's blender folder.
  2. Click the Scripting tab in the row of tabs along the very top of the Blender window.
  3. In the large text area in the middle, choose Text → Open (or press the Open button) and pick blender/make_sprites.py.
  4. Press the Run Script button, the play triangle at the top of the text area.
  5. Blender freezes while it renders, for anything from a few seconds to a couple of minutes. Wait for it.
  6. Look in your project's assets folder.
  7. Delete the old glasses sheets from assets: any -sheet.png file that is not one of your parts.

What the script does, in order:

  1. Finds every mesh object and checks which ones move between the first and last frame.
  2. Adds a camera that fits your object at its most spread out, and a light, if your scene has none.
  3. Turns on a transparent background.
  4. For each part, hides everything else and renders it on every frame. A part that does not move gets one frame.
  5. Crops each part to the box it travels through and joins its frames into one row.
  6. Writes parts.json, which records where each part sits and where it can be clicked.
Want a different angle or size? The settings are at the top of make_sprites.py. VIEW_FROM is where the camera sits and FRAME_SIZE is the render size in pixels. If you add your own camera in Blender, the script uses yours instead. Run the script again after any change to your model.

assets/parts.json looks like this:

  "height": 480,
  "parts": [
    {"id": "body", "x": 0, "y": 179, "w": 186, "h": 301, "frames": 1, ...},

FieldMeaning
width, heightThe size of the whole object area on the page, in pixels
idThe part's name from Blender, in lower case. Its sheet is assets/<id>-sheet.png.
x, yWhere the part's box sits inside the object area
w, hThe size of one frame of its sheet

Step 11: The HTML

index.html is short. The important thing is what is missing: the object's parts are not written here.

<main>
  <!-- The object. script.js adds one box here for every part in assets/parts.json -->
  <section id="object" aria-label="An object made of parts you can click"></section>

  <!-- The card that shows what each part reveals -->
  <section id="card">
    <h2 id="card-title">Pick a part</h2>
    <p id="card-fact">Each part hides a cost you cannot see.</p>
    <p id="card-source"></p>
    <button id="ask-button" hidden>Ask the model</button>
    <p id="model-output"></p>
  </section>
</main>
  • #object is empty. JavaScript fills it, so the same page works for any object.
  • Every element the script needs to change has an id.
  • The button starts hidden and appears once there is a fact to ask about.
  • Search the file for CHANGE ME to find the title and text you should rewrite.

Step 12: The CSS

This is the same sprite-sheet idea as From Shell to Sprites, Step 19. Each part is a box exactly one frame in size, with its sheet as the background. Only one frame fits in the box. Slide the background left by one frame-width and the next frame shows.

.part {
  position: absolute;
  width: var(--w);
  height: var(--h);
  background-repeat: no-repeat;
  background-position-x: 0;
  pointer-events: none;   /* the box itself ignores the mouse; see .hit below */
  transition: background-position-x 0.7s steps(var(--steps));
}

/* "apart" shows the last frame: the sheet is pulled all the way to the left */
.part.apart {
  background-position-x: calc(var(--w) * var(--steps) * -1);
}
LineWhat it does
position: absoluteLets JavaScript place the box at an exact spot inside #object, which is position: relative. Boxes can overlap.
var(--w), var(--h), var(--steps)CSS variables. JavaScript sets them on each part from parts.json, so one rule serves every part.
transition: … steps(…)When the background position changes, take 0.7 seconds over it, and jump from frame to frame instead of sliding. 12 frames need 11 jumps.
.part.apartThe end state: the sheet moved left by 11 frame-widths, showing the last frame.

There is no animation code in JavaScript. JavaScript only adds or removes the class apart. The browser sees the background position change and plays the transition, forwards or backwards.

Try it: change 0.7s to 3s and watch the frames tick. Change steps(var(--steps)) to linear to see why steps matters.

Step 13: The JavaScript

Loading the two JSON files

async function start() {
  let layout;
  try {
    const partsResponse = await fetch("assets/parts.json");
    layout = await partsResponse.json();
    const factsResponse = await fetch("data/facts.json");
    facts = await factsResponse.json();
  } catch (error) {
    cardFact.textContent =
      "Could not load the JSON files. Serve this folder with a local web server (see README).";
    return;
  }
  buildObject(layout);
}

fetch() asks the server for a file. That takes time, so await pauses this function until the answer arrives, and async marks the function as one that is allowed to pause. .json() turns the file's text into JavaScript objects and arrays. If anything fails, catch shows a message instead of a blank page.

Building the object

layout.parts.forEach((part) => {
  const el = document.createElement("div");
  el.classList.add("part");
  el.id = "part-" + part.id;
  el.style.left = part.x + "px";
  el.style.top = part.y + "px";
  el.style.setProperty("--w", part.w + "px");
  el.style.setProperty("--h", part.h + "px");
  el.style.setProperty("--steps", part.frames - 1);   // 12 frames means 11 jumps
  el.style.backgroundImage = 'url("assets/' + part.id + '-sheet.png")';

  if (part.frames > 1) {
    const hit = document.createElement("div");
    hit.classList.add("hit");
    placeHit(hit, part.start);
    hit.addEventListener("click", () => handlePartClick(part, el, hit));
    el.appendChild(hit);
  }
  objectEl.appendChild(el);
});

For each part in parts.json this makes an empty <div>, gives it the class part, positions it, hands the CSS its three variables, and sets its sheet as the background. Parts that move also get a smaller box inside, .hit, placed over the part itself. That is the clickable area, so the empty space a part travels through does not catch clicks. appendChild is the moment the box actually joins the page.

Handling a click

function handlePartClick(part, el, hit) {
  el.classList.toggle("apart");
  const isApart = el.classList.contains("apart");

  // The clickable area follows the part to where it ends up
  placeHit(hit, isApart ? part.end : part.start);

  if (!isApart) {
    return;
  }

  const fact = facts.find((item) => item.parts.includes(part.id));
  if (!fact) {
    return;
  }

  currentFact = fact;
  cardTitle.textContent = fact.title;
  cardFact.textContent = fact.fact;
  ...
}

toggle adds the class if it is missing and removes it if it is there. The CSS does the rest. Then facts.find(...) looks through the facts for the first one whose parts list includes this part's id, and writes it onto the card.

Step 14: Your facts

Open data/facts.json and replace the glasses facts with your own. Each fact needs five fields:

[
  {
    "parts": ["cap"],
    "title": "The cap: a short title",
    "fact": "One or two sentences. A number makes it land.",
    "source": "Who published it, and when",
    "url": "https://..."
  },
  {
    "parts": ["body"],
    "title": "...",
    "fact": "...",
    "source": "...",
    "url": "https://..."
  }
]
  • parts must match the ids in assets/parts.json exactly. Two parts can share a fact: "parts": ["speaker1", "speaker2"].
  • JSON is strict: double quotes only, a comma between items, and no comma after the last one. VS Code underlines mistakes in red.
  • Every fact needs a real source you have read, with a working link. The brief asks for at least four.
  • A part that does not move cannot be clicked, so it cannot show a fact.
Checkpoint Reload the page. Clicking each of your moving parts shows its own fact and a working source link. Now change the title and text in index.html (search for CHANGE ME) and the colours at the top of style.css.

Step 16: Call Ollama from your page

While Ollama runs, it listens at http://localhost:11434. A program talks to it by sending a web request: this is its API. You can try it from a terminal (Mac Terminal or Git Bash):

curl http://localhost:11434/api/generate -d '{"model": "gemma3:1b", "prompt": "Say hello in five words.", "stream": false}'

The reply is JSON, with the model's words in a field named response. The function in script.js sends exactly the same request from the page:

const OLLAMA_URL = "http://localhost:11434/api/generate";
const OLLAMA_MODEL = "gemma3:1b";

async function askOllama(prompt) {
  const response = await fetch(OLLAMA_URL, {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({ model: OLLAMA_MODEL, prompt: prompt, stream: false })
  });
  const data = await response.json();

  if (data.error) {
    throw new Error(data.error);
  }
  return data.response;
}
PieceMeaning
method: "POST"This request sends something. (Loading a file was a GET.)
headersA label on the envelope: "what follows is JSON".
JSON.stringify({...})Turns a JavaScript object into JSON text to send.
stream: falseWait and send the whole answer at once, instead of word by word.
data.responseThe model's answer, picked out of the reply.
throw new Error(...)If Ollama reports a problem, stop and pass the message to whoever called this function.

The prompt is built from the PROMPT setting at the top of script.js plus the fact on the card. Rewrite PROMPT. Whose voice should answer? A miner, a river, a repair technician, the object itself?

Checkpoint Reload your page, click a part, and press Ask the model. After "Thinking..." a short reflection appears. The first answer can take up to a minute while the model loads into memory. Later ones are quicker.
"Failed to fetch"? Ollama is not running, or you opened the page by double-clicking the file. The address bar must start with http://localhost.

Step 17: Keys, and why you need a helper server

Claude and OpenAI run on company servers and charge for each request. They know who to charge from an API key: a long secret string, like a password for programs.

A key must never go in script.js. Anyone who visits a page can read its JavaScript (right-click → View Page Source), copy the key, and spend your money. Programs that scan GitHub find leaked keys within minutes.

So the page does not call Claude directly. It asks a small program on your computer, server.js, which holds the key and passes the question on:

your page  →  server.js (adds the secret key)  →  Claude or OpenAI
your page  ←  server.js                        ←  the answer

This is what "a back end" means. The template's version is under 200 lines and needs nothing installed beyond Node.js.

  1. In VS Code, copy .env.example and name the copy exactly .env (it starts with a dot and has no other name).
  2. Your keys go in .env, after the = signs, with no spaces or quotes: 
    ANTHROPIC_API_KEY=sk-ant-...
OPENAI_API_KEY=sk-...
  3. Check that .gitignore contains a line saying .env. It does in the template. That line stops Git from ever uploading the file. Run git status: .env must not be listed.
  4. From now on, serve the page with the helper instead of Python. Stop the Python server with Ctrl+C, then: 
    node server.js
    It serves the same page at the same address, http://localhost:8000. Restart it whenever you edit .env or server.js.

On the page's side, the cloud call is small, and the same for both companies:

async function askCloud(provider, prompt) {
  const response = await fetch("/api/" + provider, {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({ prompt: prompt })
  });
  const data = await response.json();
  if (data.error) {
    throw new Error(data.error);
  }
  return data.text;
}

It posts the prompt to /api/claude or /api/openai on your own server. No key in sight.

Step 18: Call Claude

  1. Sign in to the Claude Console. This is separate from the Claude chat app, and a chat subscription does not include it.
  2. Add a small amount of credit under Billing. A few pounds lasts a long time for short answers like these.
  3. Open API keys, create a key, and copy it straight away. It is shown once.
  4. Paste it into .env after ANTHROPIC_API_KEY= and save.
  5. In script.js, change the setting to const PROVIDER = "claude";
  6. Restart node server.js and reload the page.

This is the function in server.js that does the work:

async function askClaude(prompt) {
  const response = await fetch("https://api.anthropic.com/v1/messages", {
    method: "POST",
    headers: {
      "content-type": "application/json",
      "x-api-key": keys.ANTHROPIC_API_KEY,
      "anthropic-version": "2023-06-01"
    },
    body: JSON.stringify({
      model: CLAUDE_MODEL,
      max_tokens: MAX_TOKENS,
      messages: [{ role: "user", content: prompt }]
    })
  });
  const data = await response.json();
  if (data.error) {
    throw new Error(data.error.message);
  }
  return data.content.filter((block) => block.type === "text").map((block) => block.text).join("");
}

Compare it with askOllama. The shape is the same: a POST with a JSON body, then pick the answer out of the JSON reply. Three things differ:

  • The key travels in a header, x-api-key.
  • The question is a list of messages, each with a role. That is how you would send a longer conversation.
  • The answer comes as a list of blocks in data.content. The last line joins the text ones.

max_tokens caps the length of the answer (a token is roughly three-quarters of a word), which also caps what one answer can cost. CLAUDE_MODEL is set at the top of server.js. Current names are in Anthropic's model list.

Step 19: Call OpenAI

  1. Sign in at platform.openai.com. Again, this is separate from a ChatGPT subscription.
  2. Add credit under Billing, then create a key at platform.openai.com/api-keys and copy it.
  3. Paste it into .env after OPENAI_API_KEY= and save.
  4. In script.js, set const PROVIDER = "openai";
  5. Restart node server.js and reload the page.
async function askOpenAI(prompt) {
  const response = await fetch("https://api.openai.com/v1/chat/completions", {
    method: "POST",
    headers: {
      "Content-Type": "application/json",
      "Authorization": "Bearer " + keys.OPENAI_API_KEY
    },
    body: JSON.stringify({
      model: OPENAI_MODEL,
      messages: [{ role: "user", content: prompt }]
    })
  });
  const data = await response.json();
  if (data.error) {
    throw new Error(data.error.message);
  }
  return data.choices[0].message.content;
}

Same shape again. The key goes in an Authorization header, and the answer is at data.choices[0].message.content. If you get an error about the model name, check OpenAI's model list and update OPENAI_MODEL at the top of server.js. Model names change often.

Read the output of git status before you commit. .env must not appear in it. If you ever do commit a key, deleting it from the file is not enough, because Git remembers. Go to the provider's console, delete that key, and make a new one.

Showing your work. Ollama runs on your laptop, so the model button only works on a computer with Ollama running. For a crit or the exhibition, run the page from your own laptop. If you publish the page on GitHub Pages, the object and facts will work for everyone but the model button will not, and server.js does not run there at all.

Before you call it done

  • Your object has at least four parts that animate apart, and you made it yourself.
  • data/facts.json has at least four facts, each with a source you have read and a working link.
  • One model call works, with a prompt you wrote.
  • The title, text and colours are yours, not the template's.
  • No glasses sheets are left in assets, and no key is in your repository.

Going further

  • Call the model twice with two different prompts, one from the point of view of extraction and one from care and repair, and show both answers.
  • Give parts a turn as well as a move: in Blender, press R to rotate a part on frame 12 before pressing I. If a menu appears, choose Location & Rotation.
  • Add your own camera in Blender for a different angle (Shift+A → Camera). The script uses it if it finds one.
  • More links are in RESOURCES.md in the repository.
